# Roadmap: independent progress with shared foundations

Effort and dates are intentionally not promised for the whole system. Each work package receives a bounded estimate after its interfaces and apparatus are known. Gates are evidence-based; ambitious research branches can remain open without preventing useful daily releases.

## Near-term priorities after I00

Let the current M0 finish and review its actual evidence. In parallel, approve only a small daily-assistant design/benchmark and a public-data spatial/engineering protocol if they can use separate workspaces. A printer or drone purchase is not a prerequisite for source/contract/replay work.

The first engineering result should improve a mundane but measurable fixture, not attempt an autonomous machine shop. The first RF result should establish trustworthy acquisition and generalization, not a photorealistic room. The first public gateway result should honestly distinguish local messages from internet. Those steps preserve rather than replace the ultimate aims.

## Cross-track dependencies

Identity/consent precedes real personal data. Evidence/time/frame contracts precede sensor fusion. M0's receipt principles inform—but do not dictate—the daily scheduler. Qualified physical adapters precede autonomous motion. Research protocols and workshop review precede fabrication. Independent help precedes reliance on optional drone assistance. Real hardware tests do not substitute for upstream software failure tests.

## Implementation change gate

Before any new coding package, specify baseline commit, owned files, schema changes, dependencies, permissions, tests and rollback. Before a real-world package, add apparatus identity, hazard/consent/legal review, operator supervision and recovery. A model's broader capabilities or a newly published paper do not automatically advance a gate.
