## Mandatory project behavior

- Treat every documented follow-up as additive. Keep daily assistance, both people's devices/health/privacy, cheap AI, drones, spatial RF sensing, emergency support/networking, robotics and autonomous engineering/fabrication in scope.
- First assignment is I00 reconciliation and planning. Design breadth does not authorize installs, purchases, device/account connections, public network listeners, certificate changes, or physical actions.
- Do not restart M0, change its schema, select a new Python/simulator stack or claim its tests passed. Inspect the actual application only at a user-designated path and within granted access.
- Prefer small modules and narrow typed contracts. Distinguish development threads from runtime agents. Agent count is not a product feature; useful, measurable autonomous work is.
- Separate language models from authority. No model output, retrieved text, camera sign, voice or generated skill grants privileges. No generic admin shell, raw motor/flight command or arbitrary network proxy belongs in the assistant's default tools.
- Preserve both mature concurrent-aircraft and preauthorized incapacitation observation targets. Qualify them separately; do not replace them with permanent manual-only architecture or silently enable them early.
- Consent is individual. Kennedy's data is not Eric's by default. No real health/account data belongs in fixtures or ordinary model context. Provider routing must honor subject and sharing grants before cost.
- Real-world research requires an experiment card, hazard/permission review, bounded resource/energy/time limits, stop controls, physical ground truth and independently reviewed results. Start with simulation, offline datasets or supervised low-risk fixtures.
- Engineering agents may propose and evaluate CAD/code. Fabrication and robot actions are separate gated jobs. A second LLM opinion is not structural, electrical, clinical or flight qualification.
- Recheck current primary documentation for APIs, prices, models, licenses, device support and regulations. Keep source IDs and review corrections. Archive findings rather than silently promoting old assumptions to facts.
- Report exact commands, versions, result statuses and limitations. Do not label synthetic/package tests as M0 or device acceptance. No background research/monitoring is active merely because a plan mentions it.
- Never overwrite another agent's files. Use approved ownership and isolated worktrees. No remote repository creation, push or external write unless separately authorized.
