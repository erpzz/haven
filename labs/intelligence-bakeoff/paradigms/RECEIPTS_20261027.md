# Runtime receipts and LFM2.5-8B-A1B — 2026-10-27

**Classification:** post-hoc analysis of saved records from the running paradigm
session (verifier v3, frozen held-out suite, 110 episodes, greedy, single run).
No new inference. Only aggregate counts are published here.

## Finding

LFM2.5-8B-A1B (Liquid, 8.3B total / ~1.5B active MoE, Q4_K_M) chose and called
tools almost as well as Qwen3.5-4B (tool_ok 79 vs 87 of 110) but passed far
fewer episodes (54 vs 80). Its largest failure group (25 episodes) was
*correct tools, correct facts, answer omits the evidence id or the
"not executed" status the tool returned*.

Haven already holds those values in the tool trace. `receipts.py` appends a
deterministic `Receipts:` line built only from successful tool outputs in the
same episode: evidence ids, and proposal ids with their returned authority.
It adds no note text, state or cause, so it cannot supply a missing fact, and
every `must_not` check still sees the model's own words.

| model (held-out /110) | model only | model + Haven receipts | gained | lost |
|---|---|---|---|---|
| Qwen3.5-4B | 80 | 83 | 3 | 0 |
| Nemotron-3-Nano-4B | 62 | 66 | 4 | 0 |
| **LFM2.5-8B-A1B** | **54** | **75** | 21 | 0 |
| Qwen3-4B | 44 | 51 | 7 | 0 |

Same session, measured on the RTX 2070 SUPER (8 GB), 33K context, all layers on GPU:

| model | decode tok/s @1K / @32K | prefill tok/s @8K | peak GPU MiB | load s |
|---|---|---|---|---|
| Qwen3.5-4B | 93.5 / 74.7 | 2,332 | 3,924 | 5 (cached) |
| LFM2.5-8B-A1B | 219.9 / 177.5 | 5,118 | 5,530 | 21 |

So with runtime receipts the 8B-A1B reaches 75/110 (the 4B alone: 80) at
about 2.4× the decode speed and 2.2× the prefill speed.

## Strict reading

Verifier v3 does not penalize *quoting* injected note text without obeying it.
Excluding every answer that repeats the injected instruction marker, the
receipts column becomes 83 / 63 / **74** / 51 (Qwen3.5-4B / Nemotron / LFM /
Qwen3-4B). One LFM gain is of that kind. Quoting attacker text to the user is
still undesirable and remains a separate open item.

## Routing (negative for the simple rule)

- Oracle union of Qwen3.5-4B and LFM2.5-8B-A1B: 90/110 model-only, 93/110 with
  receipts. This beats the previous local ceiling (89, which needed Strata).
- A fixed, runtime-observable escalation rule (escalate on no tool call, a
  failed tool result, or an echoed embedded instruction) escalated 31 episodes
  and scored only 59 (model only) / 78 (with receipts): **worse than the 4B
  alone.** Failed tool results are exactly where LFM is *better* (missing-note
  5/6 vs 2/6), so that signal points the wrong way. A useful router needs a
  learned or dev-split-calibrated signal; this held-out set must not be used to
  tune it.

## Limits

Single seed, one synthetic suite, post-hoc analysis designed after looking at
LFM failures. The receipts gain is a *system* result (model + runtime), not a
model improvement, and must be confirmed on a fresh run with receipts enabled
in the live runtime. LFM2.5 weights use the LFM Open License (`other`); review
it before any non-personal use.

Reproduce: `python3 -I receipts.py --session <private paradigm session dir>`.
