# Cyber intelligence architecture

## Decision record (ADR-CYBER-1, 2026-10-31)

**Context.** Qwythos-9B-v2 runs locally (Q4_K_M on an 8 GB GPU) and through Hermes Agent. It should become competent at Entra, Azure and enterprise security assessment. There is no tenant, no PowerShell, no Docker access and no paid API. The repository is public.

**Decision.** Build four separable layers that meet at one evidence model. Make every claim checkable by code before it reaches the model's answer.

1. **Knowledge**: versioned Markdown with mandatory provenance, deterministic SQLite FTS5/BM25 retrieval, and results returned as cited, untrusted reference data.
2. **Tools**: a small registry of read-only, typed, scoped and audited tools. It reuses mature scanners through output adapters (Maester, Prowler) and adds native evaluators only where nothing exists offline (Conditional Access coverage, Azure RBAC effective permissions). It is exposed to Hermes as **four** MCP tools with lazy discovery.
3. **Evidence and verification**: observations (JSON pointers into hashed raw artifacts) kept separate from findings (conclusions). An independent verifier re-derives claims and records `reported → corroborated | refuted | insufficient_evidence`; only a human sets `confirmed`.
4. **Weights**: LoRA adapters trained on verified trajectories, evaluated under the same harness (condition D) with held-out scenarios and a leakage guard.

**Consequences.** The first milestone needs no cloud account. Every component is testable on fixtures. Live tenant access is one gated tool away (`entra.graph.collect`). Model improvements are measured, not asserted.

**Rejected alternatives.**
- Exposing dozens of CLI wrappers as MCP tools: too many schemas for a 9B model.
- Embedding-first retrieval: no measured need yet, and it adds a dependency.
- Rewriting Maester/Prowler checks: duplication, and loss of upstream maintenance.
- Training before measuring: we would not know which gap a LoRA fixes.

## Data flow (vertical slice, `haven_cyber/slice.py`)

```
question ──► kb.retrieve (route domains → BM25 → ≤2 sections/doc → cited, untrusted block)
        ──► model picks a tool from registry.capabilities() / describe()      [plan]
        ──► registry.invoke(entra.ca.assess, snapshot)  (scoped path, timeout, audit line)
        ──► + evidence.normalize(Maester TestResults.json, Prowler OCSF)       [merge]
        ──► evidence.verify(bundle, raw snapshot)  → corroborated / refuted / criterion gap
        ──► model answers from VERIFIED EVIDENCE only (cites HCA ids, policy ids, [R#])
        ──► grounding_check: unknown rules / ids / refs ⇒ outcome=grounding_failed
        ──► runs/slice/<id>/record.json + records.jsonl  (input to future evaluation)
```

## Components (labs/cyber)

| Path | Layer | Notes |
|---|---|---|
| `corpus/` | knowledge | 20 documents across Entra, Azure, detection and general practice; front matter carries provenance |
| `haven_cyber/kb.py` | knowledge | parser, validator, FTS5 index, domain routing, retrieval formatter |
| `haven_cyber/tools/entra_ca.py` | tools | HCA-001..010 over a Graph-shaped snapshot; crosswalk to Maester/Prowler ids |
| `haven_cyber/tools/azure_rbac.py` | tools | effective permission with NotActions, DataActions, deny assignments and management-group inheritance |
| `haven_cyber/tools/graph.py` | tools | GET-only, allowlisted Graph v1.0 collector; token from env; gated |
| `haven_cyber/tools/registry.py` | tools | ToolSpec, validation, path scope, timeout, rate limit, audit |
| `haven_cyber/mcp_server.py` | tools | `cyber_search`, `cyber_capabilities`, `cyber_describe`, `cyber_call` |
| `haven_cyber/evidence.py`, `normalize/`, `verifier.py` | evidence | schema, two normalizers, independent verifier |
| `haven_cyber/eval/` | evaluation | scenarios builder, harness (A/B/C/D), deterministic grader, report |
| `fixtures/` | test data | synthetic tenants and tool outputs, generated by scripts in the same folder |

## Security boundaries

- **Read-only by construction.** The registry refuses `read_only=False` tools. The Graph collector issues only GETs to allowlisted v1.0 paths and refuses off-host `nextLink`s.
- **Path scope.** Tool file inputs must resolve under `fixtures/`, `runs/` or `$HAVEN_CYBER_DATA`, so the MCP server cannot read arbitrary files.
- **Secrets.** Tokens come only from the environment. They are never logged, and the audit log stores an input hash, not arguments.
- **Untrusted content.** Retrieved text and tool output are wrapped and labelled as data, and the grounding check rejects invented identifiers.
- **Live tenant access** needs `HAVEN_CYBER_ALLOW_LIVE=1` plus an operator-supplied token and emergency-account list. Nothing escalates privileges, writes configuration or widens targets.
