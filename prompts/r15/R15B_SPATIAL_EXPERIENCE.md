# R15B — Spatial admin experience and cooperative field use

Design the experience of Haven Observatory: exciting, understandable and useful, not an overloaded intelligence-themed dashboard. This adds to the two-person daily assistant, RF/spatial research, robotics and engineering branches; it does not replace them.

## Inputs

At a recorded commit of https://github.com/erpzz/haven read the root instructions, `coordination/R15_OBSERVATORY.md`, the full R15 master prompt, `design/H00/R15/brief-v1/OPPORTUNITIES.md` and issue #12. Use the actual GEV fork at https://github.com/erpzz/gods-eye-view for source-grounded feature claims. Read available R01/R03/R04/R07/R14 findings only after identifying actual paths/versions; unavailable findings remain pending.

## Work

Design desktop, phone and optional future glasses journeys around world inspection, replay, scenario forks, uncertainty, owned resources, engineering lineage, shared field pins and public regional awareness. Show a default small workspace, an expanded analysis mode and a mobile field mode. Use textual wireframes or non-executable layouts; do not implement an app.

For each journey specify user intent, displayed evidence, action meaning, feedback, interruption, offline behavior and the simpler current alternative. Include live-versus-historical-versus-simulated distinctions that do not rely only on color. Never equate a virtual camera movement with device motion. Private/shared/public modes must remain legible, including a shared screen or speaker. Treat headset/glasses input and display as model-specific and unqualified.

Develop five compelling experiences with realistic success criteria. Explain the 'inspect element for the physical world' interaction and planet-to-workbench lineage in particular. Preserve direct access to ordinary personal-assistant tasks. Compare a dramatic aesthetic with cognitive load, latency, accessibility and error recovery; fun should support understanding.

## Return and boundaries

Proposed output `design/H00/R15/inputs/R15B/v1/`: EXPERIENCE.md, USER_JOURNEYS.md, USABILITY_PROTOCOL.md and SUMMARY.md. Include at least six finite usability scenarios, expected misconceptions, measurable comparison with separate tools and exact interface/permission questions for H01/H04/H07/H08.

No real participant recruitment, health/location data, screenshots of private accounts, device enrollment, model calls, installations, repository edits or automatically started agents. Public research and design only. Label all interactions illustrative and human tests NOT_EXECUTED. Stop with a prioritized first experience and a one-page handback.
