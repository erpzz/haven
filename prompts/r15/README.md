# Optional R15 specialist assignments

Start with the [master R15 prompt](../R15_GODS_EYE_OBSERVATORY_AND_OPEN_TOOLS.md) and [coordination entry](../../coordination/R15_OBSERVATORY.md). These are ready-to-use research prompts, not running agents or completed findings.

| ID | Prompt | Owned question | Suggested wave |
|---|---|---|---|
| R15A | [Fork audit](R15A_FORK_AUDIT.md) | What can we actually reuse from the exact fork? | First, only if splitting the master task |
| R15B | [Spatial experience](R15B_SPATIAL_EXPERIENCE.md) | Which interactions make the admin POV genuinely useful and enjoyable? | First |
| R15C | [Sources and economics](R15C_SOURCES_AND_COSTS.md) | Which sources and tools fit the rights, offline and cost requirements? | First |
| R15D | [Haven integration boundary](R15D_HAVEN_BOUNDARIES.md) | How do views, private context, jobs and permitted actions connect? | After A and relevant R03/R02 decisions |
| R15E | [Replay and scenarios](R15E_REPLAY_AND_SCENARIOS.md) | How do history, uncertainty and alternate scenarios remain evidence-preserving? | After A and initial R06/R07 inputs |
| R15F | [Independent evaluation](R15F_VALIDATION.md) | What is the smallest integration worth building, and how could its claims fail? | Early rubric review, then integrated handback review |

Run one integrated R15 study first unless a split has a clear benefit. Use at most two or three active specialist tasks when separately assigned. Research may proceed provisionally around a pending owner decision; implementation must not invent that decision. These roles are development organization, not a required six-agent runtime.

Every prompt is bounded to public research and design. No automatic launch, code execution, installations, accounts, device actions, GitHub writes or merges. Future publication needs a separate instruction. Keep results out of brief-v1 and link the exact source versions. Follow [issue #12](https://github.com/erpzz/haven/issues/12) for coordination.
