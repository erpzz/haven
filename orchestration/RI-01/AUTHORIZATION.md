# RI-01 — Authorized autonomous scope

## Request and launch
The user requested a real multi-agent Codex workflow that reviews each research addition, consults between agents, completes remaining research using prior findings, integrates the design, preserves the vision, and independently reviews code. They subsequently required visual recognition and the full multimodal suite, not language-only models.

This publication prepares that workspace. The user launches the campaign by submitting START_CODEX.txt in a Codex session. Publication alone does not run agents. The scope below applies to that launched campaign, not all future repository work.

## Explicit exception to old no-subagent instructions
The RI-01 supervisor MAY spawn, message, wait for, interrupt, resume and close actual native Codex subagents within its limits. It MAY automatically advance from one completed research handback to the next eligible task, ask authors for revisions and route peer consultations. The old one-thread prompts that said 'do not start agents' or 'stop at this handback' are source-era restrictions superseded ONLY for this expressly requested, bounded campaign. Other scope limits remain. Children cannot recursively spawn agents; the supervisor owns all dispatches.

Do not answer by handing the user more prompts to distribute. Execute the research-and-review graph until done, the resource ceiling, or a genuine blocking condition. Routine, reversible documentation choices are the integration manager's job, not repeated user questions.

## Authorized work
- Read this repository, its branches, PRs, comments and explicitly linked project sources; inspect the owner's gods-eye-view fork read-only.
- Conduct public web research using existing approved tools, including primary-source papers, documentation, figures, licensed examples and available media.
- Use existing image-viewing, PDF-rendering, media-decoding and audio-inspection tools where available. Record exact modality and transformations. No downloads of executable tooling or model weights.
- Read the actual available project code and test evidence. Use a supplied project artifact or an explicitly designated local project snapshot for missing source, not unrestricted searches of the user's computer.
- Create and edit new campaign documents, dependency records, proposed interface definitions, source inventories and work-package plans in assigned campaign paths. Preserve original source artifacts. Use existing Python standard-library parsing, hashing and coordination checks; do not run retrieved application, CAD, firmware or installer code.
- Create a new isolated project checkout or use a clean designated Haven checkout; record the actual host and path. Workers write only their assigned report directories; the supervisor alone operates the shared Git index and publishes checkpoints.
- Commit and push the campaign branch and open/update ONE consolidated PR plus concise issue receipts using the existing GitHub authorization. No token creation or credential changes. A successful local commit is not a successful push; read back the remote ref.
- Resolve reversible design alternatives for campaign synthesis with evidence and dissent recorded. A research selection is not an operator implementation grant.

## Not authorized
No product implementation, application merge, deployment, M0/M1/M4 changes, NIGHT-01/R1 repair, privileged setup, new packages/models/frameworks, new paid-provider calls, purchases, private account/health/household data collection, cameras/microphones/sensors activation, aircraft/robot/printer operation, network exposure, webhooks, scheduled jobs or GitHub Actions invocation. No blanket history rewriting, branch deletion, force push or bypass of existing permissions. Do not execute or activate the unfinished .import/ importer or modify its workflow as a shortcut.

Subagent usage through the selected Codex session is expected and uses that session's allowance. '$0 additional provider spend' does not mean the session itself is free or unlimited. Honor host/account usage controls; do not create an API account as a fallback.

## Public repository boundary
Use synthetic or suitably licensed public examples. Do not publish credentials, host inventories, exact home layouts/locations, real health data, household media, private messages, runtime databases or employer information. Public research does not authorize private-person dossiers, covert tracking, face identification, weapons targeting or access-control bypass. Research medical/augmentation possibilities with appropriate evidence; no DIY invasive procedures, stimulation protocols or treatment recommendations.

## Default envelope
At most 3 open child-agent threads plus the supervisor; lower host limit wins. At most 8 wall-clock hours per launch, 64 dispatched assignments including reruns, 2 revision rounds per finding, and 250 MiB of public research assets in the private working area. Do not republish third-party media by default. Stop early when complete. Reserve the final 15 minutes for checks, checkpoint, child shutdown and delivery. Inability to measure token spend means UNKNOWN, not zero; use observed call/task counts and the wall-clock cap.

At a cap or account interruption, persist a resumable queue and clearly name unfinished tasks. Resume requires the user's resume command; no detached jobs, automatic rescheduling or promise of background continuation. A finite launch may not complete all research.

## Review gate
The supervisor can integrate independently reviewed research into a campaign branch without asking after each file. It does NOT merge research PRs or the final campaign into main automatically. The final deliverable is a coherent PR and proposed coding packages for one operator review, not a new implementation disguised as research. Existing code review is read-only; unavailable code must be reported as unavailable.
