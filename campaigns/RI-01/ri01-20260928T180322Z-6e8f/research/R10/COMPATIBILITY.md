## Concrete API boundaries

**DJI.** `IVirtualStickManager.enableVirtualStick`, `setVirtualStickAdvancedModeEnabled` and `sendVirtualStickAdvancedParam` are concrete control APIs; the latter is documented since 5.1.0 with a recommended 5–25 Hz sending rate. `FlightControllerKey.KeyAircraftLocation3D`, `KeyAircraftAttitude`, `KeyIsFlying` and `KeyAreMotorsOn` are telemetry examples. `ICameraStreamManager` provides available-camera listeners, compressed stream listeners, frame listeners and display surfaces; the manager is documented since 5.8.0. H.264/H.265 transport/frame callbacks do not by themselves establish trusted camera capture timestamps. SDK callbacks/errors, a refreshed aircraft state and independent observed outcome have different meanings. No API credentials were created. [S06–S08]

**PX4/MAVLink.** Distinguish onboard uploaded missions from continuing offboard setpoints. PX4 v1.16 documents >2 Hz offboard continuity, `COM_OF_LOSS_T` and `COM_OBL_RC_ACT`; actual values, supported frames and independent takeover are qualification inputs. Preserve the v1.16 parameter reference when the overview abbreviates enum values. A video camera being controllable through MAVLink's camera protocol does not mean MAVLink carries decoded video or that the payload has that protocol. [S22–S24]

**Crazyflie.** CRTP has distinct command/logging/localization services. Its 24-bit boot-relative millisecond logging timestamp needs explicit rollover and boot-epoch handling in an adapter; a reconnect cannot silently reuse the old epoch. AI-deck image streaming is separately provisioned firmware/example software. [S18–S20]

## Required qualification record for every proposed device

Record exact purchased/supplied identifiers only under a future authorized private enrollment flow; publish pseudonymous IDs and public model/version facts. Freeze aircraft/controller/bridge/SDK/configuration and each needed API response, declared units/frame/time semantics, authentication/offline dependencies, video decoder/codec settings, on-aircraft control mode and manual recovery behavior. Required feature absent, undocumented datum, stale firmware profile or unexpected vehicle identity => deny that feature and report the specific missing field. A valid simulator profile must never match a real-aircraft profile.

The catalog is a **candidate list**, not an automatic discovery workflow. No scanning, pairing, activation, binding, login, firmware modification or provisioning occurred. These remain separately authorized and reviewed work.
