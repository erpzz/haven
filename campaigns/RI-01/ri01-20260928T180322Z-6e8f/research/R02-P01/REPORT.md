## Decisions and alternatives

Retain logical modules within the existing small application, with a separately supervised worker only where a bounded native/inference task requires it. Do not make six logical interfaces into six deployed services. Keep source records and a transactional ledger in the existing SQLite direction; no mandatory vector store, queue broker, model swarm or framework.

A monolithic coordinator without an independently surviving worker supervisor is simpler but cannot satisfy E0-H1 after abrupt coordinator death. A framework replacement adds unmeasured lifecycle, memory and hidden-call surfaces without solving authority. A shared inference server may save model memory but requires explicit request cancellation and occupancy evidence; closing a client connection is insufficient. Prefer a single owned local inference process for initial controlled evaluation if the operator can provision it within an approved host envelope. This is a proposed experiment topology, not a claim about the installed M4 setup.

## Minimal proposed interfaces

These are reviewed design proposals for a new internal version; frozen v1 fixture schemas and active M0/R1 code are unchanged.

1. **Coordinator:** admit immutable request/context/budget references, choose only eligible routes, allocate an attempt, collect typed result, and request publication or a domain proposal. It owns no implicit identity, grants or physical success. Same request key plus same payload returns the same record; different payload conflicts. Unknown external writes enter reconciliation and are never automatically replayed.
2. **Context and authority:** evaluate(principal, subjects, purpose, audience/device, source revisions, provider/data class) returns a restricted packet plus authority vector and omissions. Cache keys include the vector, model/template/tools and media transforms. Context creation never turns a model-authored permission field into authority. R03 owns real identity/joint-grant policy.
3. **Memory/evidence:** propose and compare-and-swap commit use expected revision, source refs, retention rule and authoritative requester. Committed corrections/deletions increment source revision/tombstone and invalidate dependent summaries, embeddings, queued packets and cached results. Return actual commit sequence and propagation states. Model inferences remain proposals. Restore must merge current revocations/tombstones before serving old data; missing current ledger means unavailable.
4. **Worker:** submit exact attempt specification; observe computation state; request stop; obtain independently observed termination receipt. Grants and publication permissions remain outside the worker. Children are disabled in the first implementation. Worker output cannot renew a lease or expand a budget.
5. **Model adapter:** accept an immutable scoped packet, exact capability profile, token/media/elapsed cap and reservation reference. Return normalized text/typed claims, refusal/finish state, actual artifact/version when exposed, original usage categories and cancellation observations. Unsupported modality/schema/tool support is ineligible, not silently coerced. No SDK object or hidden reasoning trace is the domain contract.
6. **Release and ledger:** publication gate and monetary ledger provide separate transactions/receipts. A release authorization does not mean delivered; a completed model call does not mean semantic correctness; a cancelled job does not mean zero charge.

### F01: publication ordering — actual R03 consultation, provisional pending review

Propose one authoritative transaction boundary for the synthetic single-host slice. Revoke, correct, cancel and authorize-release all serialize in that authority store. authorize-release re-reads the entire principal/session/device, audience/purpose, source/grant/policy vector, cancel epoch, restore epoch and lease fence; checks expiry; appends an immutable release receipt, unique sequence, output digest and outbox reference; and commits. A failed or unknown commit never licenses sending. A contended transaction yields no usable release receipt. Use a fresh write transaction, not an old read snapshot upgraded after inference. SQLite's single-writer design supports this local ordering, while busy/commit failure still needs explicit handling [P01-S01,S02].

Do not hold a database transaction open across remote IO. Separate release_state from delivery_state. An authenticated destination must revalidate online and consume a one-use exact-output/chunk permit immediately before display/playback; session/device/audience epochs are checked and consumption separately recorded. A reusable pre-revocation bearer receipt must not bypass revalidation. Consumption is idempotent per output/destination/sequence, while a lost acknowledgment never authorizes blind redisplay. Reconnect discards old permits and requests new authorization. Delay, lost acknowledgment or crash yields DELIVERY_UNKNOWN; retry requires new current authorization and duplicate-display handling.

This establishes an ordering of authorization, not instantaneous revocation of bytes already in transit or disclosed. Define that privacy contract explicitly. A single local release owner can order enqueue and revoke events; it cannot recall a person's perception. R03 explicitly acknowledges that the permit response can race a subsequent revocation: already-issued/in-flight disclosure cannot be recalled instantaneously. This consulted protocol still requires independent design and implementation review; private remote speaker/overlay delivery stays unqualified. Synthetic tests must exercise revoke-first and release-first orders, delayed delivery, reconnect, duplicated receipts, device rebinding and correction after selection.

### F02 / Q-CORE-01: suppression versus computation termination

Minimum C05/C09 extension:

- execution_ref: attempt_id, worker_instance_id, boot_id, lease_fence and ownership_scope; use a nonce/creation identity, never a PID alone.
- publication_state: NOT_RELEASED, SUPPRESSED, RELEASE_AUTHORIZED, DELIVERY_UNKNOWN or DELIVERED.
- compute_state: NOT_STARTED, RUNNING, STOP_REQUESTED, STOP_CONFIRMED or UNKNOWN.
- cancel_epoch; deadline; state_revision; stop_evidence_ref nullable.
- stop receipt: exact execution_ref, observer identity, observed_at, stopped scope, observation method, exit/result evidence and remaining remote/shared work status.

SUPPRESSED and STOP_CONFIRMED are independent facts. A cancel request increments the epoch and stops admission immediately. Owned computation becomes STOP_REQUESTED until the supervisor observes termination of the declared scope. A lease expiry, kill request, dead coordinator, withheld answer or missing heartbeat cannot itself produce STOP_CONFIRMED. On lost coordinator observation, fence publication and use UNKNOWN computation until reconciliation.

For a local process, a surviving supervisor must observe exit/reap bound to the actual instance and verify any permitted descendants in its containment scope. A wrapper-only receipt cannot cover a shared model server or paid provider. Shared/remote computation remains UNKNOWN unless its own qualified receipt confirms termination. Billing stays independently unknown. The Python3.12 documentation confirms terminate/kill can skip finally handlers and leave descendants; the archived parent-finally cleanup is not a surviving supervisor [P01-S03].

### F06: conservative accounting

Keep current NIGHT-01 external spend strictly zero. A future ledger uses reservation_id/generation, immutable scope/rate revision, admitted_at, original usage, settlement_id and reconciliation status. In one transaction ensure charged plus outstanding conservative exposure stays within each applicable job/user/household/provider allowance. Parent-child slices partition a reservation; they never mint capacity or charge a parent and child twice.

Before dispatch persist admitted exposure. An unadmitted reservation may expire and release its unused allocation. Once admitted, timeout, cancellation, process death, connection loss or expiry retains worst-case exposure. If dispatch outcome is ambiguous, treat it as admitted. Reconciliation may replace the bound with reliable usage or an explicitly authorized conservative terminal charge of the full bound; that is not a refund. Duplicate settlement IDs are no-ops; conflicting repeats fail. Unknown usage remains unknown, never zero.

Preserve provider categories and their documented overlap. Compute a conservative rational sum before rounding upward to integer micro-USD; store original precision and provenance. Unsupported billable categories, rate changes or an unbounded billable path make a route ineligible. Conservative under-utilization is preferable to silently spending beyond the approved cap. No paid adapter is introduced in the first coding package.
