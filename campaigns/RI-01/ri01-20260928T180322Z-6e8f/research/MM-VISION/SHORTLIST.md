No current primary source establishes universal best speed/accuracy for these mixed tasks. Parameter count is not peak memory. Approximate uncompressed weight storage `parameters × bytes/parameter` is only a planning lower component; activations, KV/state, vision tokens, decoder buffers, library overhead, compilation and concurrent users can dominate. Quantization may reduce weights while changing OCR/localization and not improving wall time. SAM's video memory grows with profile/object/frame handling; do not assume one image peak covers a long clip.

## Routing and full cost accounting

1. Admit the exact task, original/region and current full dependency closure. Reject unsupported data, oversized decoded dimensions or unbounded media before inference. Authorization failures never trigger a stronger provider.
2. Use metadata/exact lookup for known facts; use only required local task processors. Cache by source revision, transform, model/runtime/profile, current authority dependencies and calibration; no cross-user cache leak.
3. If the local output is uncertain, return useful supported portions and explain uncertainty. One separately budgeted reprocess/crop may be proposed when the original has sufficient pixels. Enlarging a tiny crop does not restore information.
4. Stronger local VLM or an eligible hosted multimodal route is an optional later escalation with exact provider/model/price/data-policy and egress authorization. No hosted provider selected, no price quoted, no paid calls authorized here. Exhausted budget or denied egress yields a bounded answer/abstention, never hidden fallback.

Record cold load/compile, decode, preprocessing, inference, postprocessing, retrieval/authority, output validation and queue wait separately; report first useful answer and total wall-time p50/p95, throughput, CPU/GPU occupancy, peak RSS/VRAM, watts/Wh when independently measured, bytes stored/transferred and contention/cancel behavior. Measured resolution, image count, batch, dtype, model digest, runtime, drivers and warm/cold state accompany every result. Published GPU FPS omits enough context that it cannot be a service SLO.

`cost_per_success = (amortized hardware + energy + storage/backup + network + provider charges + setup/maintenance + failed/retried work + human review) / independently successful authorized tasks`. Show numerator components and denominator, abstentions and invalid tasks separately. License fees may be zero while total cost is not. Host acquisition/amortization, tariff, storage, maintenance time and provider costs are UNKNOWN here. Pilot budgets are allocations, not feasibility estimates. Include reservation/settlement unknowns after cancellation, and per-user fairness/latency rather than average throughput alone.
