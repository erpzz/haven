# Specialist threads and ownership

H00 is the integration owner. H01–H07 retain the prior everyday/intelligence/tools/privacy/aircraft/assurance/wearables split; H08–H12 add spatial research, engineering/fabrication, ground robotics, emergency communications and evidence research. The existing Codex M0 thread remains a **separate active implementation owner**, not a new task to assign to H00.

At most two or three specialist threads should work concurrently initially. This is a practical coordination recommendation, not a limitation on ultimate capability. Each receives a versioned, minimal context packet and explicit file ownership. Do not assume automatic cross-chat memory or synchronization.

## Proposed waves

**Wave 0:** H00 runs I00, publishes the scope/contracts and asks H04/H06 for an early boundary/test review. No new application code.

**Wave 1:** H01 everyday experience and H02 economics against the shared identity/authority model. H07 may research public APIs concurrently only if the active-thread budget permits.

**Wave 2:** H03 connectors and H07 native wearables once scope/consent contracts are reviewed. H08 can perform dataset/interface research without hardware.

**Wave 3:** H08 spatial experiments and H09 mechanical fixture campaign; H10 owns a separate robot path once useful tasks are defined. H12 sources relevant research rather than creating a giant unrelated backlog.

**Wave 4:** H05 physical aircraft qualification and H11 emergency/guest networking after baseline gates, with independent H06 review. S1/S2 simulations preserve concurrent aircraft and standing incapacitation goals.

H12 and H06 are review roles throughout, not a mandatory permanently running agent. Integrate each handback before opening another wave. A fast successful branch need not wait for every speculative research goal, but it cannot assume a missing upstream safety/identity contract.

## Runtime is different

The roles in docs/13_RUNTIME_AGENTS.md are proposed product workers. They may be jobs in one coordinator or isolated services for concrete reasons. Opening thirteen development chats does not justify deploying thirteen always-on models. Real useful autonomy is evaluated by completed authorized tasks and physical evidence, not by worker count.

## Branch and merge discipline

Use a separate documentation repo or approved isolated worktree per coding package. No shared application working tree with the active M0 thread. Specialists submit proposed diffs and contract change requests. H00 reconciles interfaces; domain owners review; H06 evaluates evidence; Eric approves promotion. Do not create/push a remote repository without separate permission.

Context packet: requirement IDs, baseline/contract hashes, owned files, scope/exclusions, source IDs, current unknowns, budget and exact expected handback. Result packet: changed paths/hashes, decisions, commands if any, test results, evidence, sources, unresolved assumptions, proposed next step and approval needs.

See registry.json and individual Hxx_STARTER.md files for self-contained assignments.
