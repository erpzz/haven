# JEV-01 acceptance — real application integration, honest provider evidence

This protocol is part of [START_HERE.md](START_HERE.md). It is a **test specification**, not a report of executed checks. Its offline work uses the existing IP-02 environment, deadline and deterministic-suite budget. No real TypeSafe connection, model-listing request, API key, new dependency or live Jev allocation is granted. Preserve failed attempts and exact candidate identities.

## Independent preparation

The QA executor must be independent from the implementation author and must not repair candidate code. Bind an immutable candidate/config/dependency snapshot. Record real native identities and source drift. Create invented notes/questions in two separate demo sessions. Inject synthetic TypeSafe-shaped responses through a test-only transport and instrument outbound creation so any real provider request fails the test before a socket or DNS lookup. Use actual app/authority/storage code around that transport, not an entirely simulated Haven pipeline.

Record three different evidence classes: author unit checks; independently executed app/HTTP/browser/fault checks using synthetic transport; and real provider behavior, which is **NOT_EXECUTED** in this assignment. No fixture output is relabelled as model output. Capture actual screenshots only when a browser actually runs. Public reports contain synthetic examples and sanitized records, never credentials, raw private traces or personal data.

## Required offline cases

| ID | Exercise | Required observations |
|---|---|---|
| J01 | Provider disabled, missing grant/key, normal startup, status and UI refresh | No hosted request or secret lookup; deterministic flow remains available; no automatic fallback to another provider. An enabled flag without the required trusted grant stays closed. |
| J02 | Real adapter serialization and response parsing through a synthetic transport | Exact fixed endpoint/model and expected request shape; finite typed results; exact question/candidate/model binding. Reject missing/extra question IDs, unexpected options, malformed distributions, inconsistent result types, NaN/infinity, oversized responses and model drift. State the numerical tolerance used for probability sums. |
| J03 | Text contains instructions to change endpoints, grants, model, credentials or execution | Content remains data; no field/host override or extra capability. No semantic probability can upgrade an authority denial. This is local transport/application testing, not security testing of the hosted service. |
| J04 | A-private, explicitly shared, revoked, tombstoned, expired and exhausted sources | Deterministic authorization filters before scoring. B's decision state contains none of A's forbidden content. Explicit ineligible selection receives a clear denial; no silent source/grant substitution. High fake relevance does not change that. |
| J05 | Pause decision; then correct/revoke a selected OR scored-but-unselected input | Entire decision-input ancestry is checked; stale proposal is rejected and cannot release downstream content. Recheck grants, revision, session, restore/cancel/fence epochs. No removing an inconvenient influencing source after scoring. |
| J06 | Pause decision while another transaction changes a note | No database transaction is held across provider waiting. The independent write proceeds; the stale decision cannot subsequently pass sealing. Record the measured sequence, not just a mock assertion. |

| J08 | Low/ambiguous scores, no relevant passage, empty candidate set | No forced spurious source; policy is visible, versioned and deterministic. Empty selection does not create a model call. Fixture thresholds prove branch behavior, not calibration. |

| J14 | Integrated ordinary-controls journey and baseline comparison | Save/read/share a synthetic note, use explicit input selection, obtain a source-linked result, and observe accurate completion/fallback without author state repair. Record steps, elapsed time, errors and retries versus simply opening the source. Do not invent human preference or live semantic improvement. |

These are coverage requirements, not a mandate to multiply nearly identical tests. Keep representative positives alongside denials. Retain relevant existing IP-02 privacy, finite/joint-grant, once-only output, authority/egress and CF-F01–04 checks. Altered source invalidates affected prior findings until independently rechecked. All formal final starts, including harness failures, consume the existing three-start allowance; there is no separate JEV-01 final budget.

## Review and delivery gate

Independent CODE review must inspect the actual async transaction boundary, pre-send authority, remote-default-off gate, typed parser, complete decision ancestry, cancellation, logging and no-retry behavior. VISION review checks whether the result improves clarity and preserves the wider Haven scope without pretending Jev sees images or writes answers. EVIDENCE review reconciles candidate bytes, actual executor identity, requests/attempts, failures, claimed benefit and the distinction between simulation and provider observation. No author or H00 synthesis accepts its own implementation.

The local deliverable can pass as **JEV_READY_OFFLINE_TESTED** with **JEV_LIVE_NOT_EXECUTED**, provided the real adapter is connected to the actual app seam, required offline evidence exists, unresolved critical findings are not waived, and the default local flow remains usable. A disconnected adapter is only IMPLEMENTED_PARTIAL. If a browser or native tool is unavailable, preserve the exact gap rather than replacing it with screenshots or fictional consultation.

## Future live qualification — deliberately not authorized here

Before the first hosted request, a separate operator-controlled record must supply data/purpose authorization, approved TypeSafe credential provisioning outside chat/GitHub, applicable terms, numerical request/token/spend caps, per-call and total deadlines, failure/retry policy, model pin, and a root-owned provider gate. A key or vendor rate limit is not a budget. Use independently labelled synthetic English text first; no personal/employer sources or protected old holdouts. No provider security probing, purchases, or account setup follows from this protocol.

Freeze representative cases and criteria before calls, including synonyms versus lexical baseline, irrelevant notes, no-match cases and ambiguity. Measure semantic selection quality, precision/coverage or appropriate task loss, uncertainty calibration only with an adequate labelled sample, end-to-end p50/p95 latency, actual requests/tokens, unknown exposure and attributable dollars. Keep rates and trials versioned; small samples have explicit uncertainty. For comparison, distinguish actual Jev requests from existing local generation and compare complete user journeys, not just vendor inference latency.

All repeats, failures and cancellations count. Do not use the old Qwen pilot allocation or change thresholds after seeing the final results. Preserve provider-reported usage separately from confirmed billing; unavailable costs are UNKNOWN. Adoption is justified only by demonstrated usefulness within the approved privacy/resource envelope. Results that are slower, less useful or inconclusive are valid findings, not permission to enlarge scope or fabricate success.
